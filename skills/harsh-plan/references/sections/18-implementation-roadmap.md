# Section 18: Implementation Roadmap

**Key:** `implementation_roadmap`

## Purpose

Holds the build order **inside the same meta doc** as the blueprint. Stage 0 is discovery (skill Phases 0–4). Stage 1+ are confirmed after Stage 0 approval.

## Questions

- What should be built first after Stage 0?
- What dependencies exist between stages?
- What milestones exist?
- What defines completion of each stage?
- Which design frame/section links belong to each stage?

## Required output

During Stage 0 (before approval): draft intent for build order is fine — enough that MVP path is obvious.

After Stage 0 approval (Phase 5): ordered Stage 1+ with deliverables, done-when, and per-stage design links — written into this section of the meta doc. User confirms order before lock-in.

## Minimum bar for `complete` (during Stage 0)

Enough phase intent that a post–Stage 0 mapping is possible. Exact Stage 1+ table may be finalized in Phase 5 after approval.

## Note

Do **not** create a separate whole-app implementation plan. File-level HOW for each stage comes from `ce-plan` when that stage starts — not during Stage 0.
